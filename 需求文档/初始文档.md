# 产品需求文档 (PRD)：NovelForge AI (桌面版)

**版本：** V1.0 (MVP)
**日期：** 2026-05-13
**目标用户：** 网文作者、传统文学创作者、编剧（需处理长文本逻辑）

---

## 1. 产品愿景与核心价值
**愿景：** 打造一款“懂剧情、记设定、不瞎编”的 AI 长篇小说写作伴侣。
**核心价值：**
1.  **无限上下文：** 解决大模型“记性差”的问题，通过摘要+RAG技术，让AI始终掌握全书剧情。
2.  **逻辑守门员：** 自动检测伏笔遗漏和设定冲突，防止剧情崩坏。
3.  **沉浸无干扰：** 功能强大但界面克制，绝不打断作者的心流。

---

## 2. 整体架构与交互逻辑 (解决“臃肿”问题)

采用 **“三栏 + 情境浮层”** 设计，严格遵循 **“写作时隐身，需要时现身”** 原则。

| 区域 | 内容 | 交互逻辑 |
| :--- | :--- | :--- |
| **左侧栏** | **项目导航** | 仅显示章节树、大纲视图。默认窄栏，Hover展开。写作时可完全折叠。 |
| **中间区** | **编辑器** | 纯文本/Markdown。支持右键菜单唤起AI功能。 |
| **右侧栏** | **AI 助手** | **默认收起**。选中文本或按下 `Ctrl+Space` 唤出。根据选中内容动态切换面板（如：润色面板、问答面板）。 |
| **底部栏** | **状态中心** | 极简图标（时间轴、回收站、设定库）。仅在触发全局扫描时展开。 |

---

## 3. 详细功能需求 (Feature Specs)

### 3.1 核心写作与项目管理
*   **FR-001 项目结构：** 支持创建项目，包含“卷 -> 章 -> 节”层级。
*   **FR-002 本地存储：** 所有文稿以 `.novel` 格式（本质是加密的SQLite或文件夹结构）保存在本地，保障隐私。
*   **FR-003 版本快照：** 每次手动保存时，自动生成版本快照，支持一键回滚。

### 3.2 AI 上下文引擎 (Context Engine) —— *核心*
*   **FR-004 章节摘要自动生成：**
    *   触发：手动点击或章节完成后自动后台运行。
    *   产出：短摘要（50字，用于列表）、长摘要（500字，用于AI上下文）。
    *   存储：存入向量数据库，关联人物、地点标签。
*   **FR-005 角色/设定卡：**
    *   允许用户手动创建或AI自动提取“人物卡”、“道具卡”、“势力图”。
    *   在AI对话时，强制注入当前相关卡片信息，防止OOC（Out of Character）。

### 3.3 对比决策模式 (What-If Mode)
*   **FR-006 分支推演：**
    *   **入口：** 选中文本 -> 右键 -> “对比分支推演”。
    *   **UI：** 弹出模态框，分三栏显示。
        *   **A分支（稳健）：** 符合现有逻辑的正常发展。
        *   **B分支（激进）：** 包含反转或高风险高回报。
        *   **C分支（黑天鹅）：** 意外事件介入。
    *   **输出：** 每种分支包含“后续300字预览”及“蝴蝶效应分析”（对结局的影响）。

### 3.4 剧情时间轴可视化 (Timeline)
*   **FR-007 时间轴生成：**
    *   基于章节摘要，自动解析时间、地点、人物。
    *   生成可视化的“甘特图”或“流程图”。
*   **FR-008 逻辑冲突检测：**
    *   **时间悖论：** 检测到“第10章过了三天，第11章还是同一天”。
    *   **空间瞬移：** 检测到“无转场描写的地理位置跳跃”。
    *   **表现：** 在时间轴上标红预警，点击跳转至冲突章节。

### 3.5 废稿回收站 (Gold Mining)
*   **FR-009 智能回收：**
    *   不仅仅是删除文件，而是监听编辑器剪切/删除操作。
    *   自动将删除的大段文本存入“回收站”，并打上标签（如：废弃设定、备用金句）。
*   **FR-010 废稿召回：**
    *   当用户写作陷入瓶颈时，可搜索废稿库关键词（如“刺杀”）。
    *   AI推荐：“检测到您在第3章删除过一段关于‘毒药’的描写，是否复用？”

### 3.6 基础AI功能 (润色/续写/检索)
*   **FR-011 润色：** 选中文本 -> 右侧栏出现润色选项（更华丽/更简洁/更有张力）。
*   **FR-012 检索：** 侧边栏输入框输入自然语言，如“找一下张三第一次出现的章节”，AI通过向量库精准定位。
*   **FR-013 大纲生成：** 输入“我要写一本都市修仙”，AI生成粗纲 -> 确认后生成细纲 -> 确认后填充章节骨架。

## 4. 技术需求 (Technical Specs)

### 4.1 技术栈
| 层级 | 技术方案 | 备注 |
| :--- | :--- | :--- |
| **桌面端** | **Tauri (Rust + WebView)** | 比Electron更轻量，性能更好，适合处理本地大文件。 |
| **前端** | React + TypeScript + Tailwind CSS | 组件化开发，易于维护。 |
| **后端** | Rust (业务逻辑) + Python (AI接口) | Python负责调用LLM API和Embedding模型。 |
| **数据库** | SQLite (本地) | 存储书籍结构、设定、摘要。 |
| **向量库** | **LanceDB (本地)** | 嵌入式向量数据库，无需单独部署服务，隐私性好。 |
| **AI模型** | OpenAI / Claude / DeepSeek API | 预留接口，支持用户自定义Key。 |

### 4.2 上下文管理策略 (Context Management)
为确保AI不乱说话，采用 **"System Prompt + RAG"** 策略：
1.  **System Prompt 锁定：** 明确告知AI：“你是一个助手，严禁修改用户原文设定，除非用户明确要求。”
2.  **动态注入：**
    *   `User Input` (当前指令)
    *   `Current Chapter` (当前章节全文)
    *   `Related Summaries` (通过向量检索到的相关章节摘要)
    *   `Character Cards` (涉及的角色卡)
    *   `Constraint Rules` (硬性约束，如：世界观限制)

## 5. 非功能性需求 (NFR)
*   **性能：** 打开百万字级别的项目，延迟不超过 500ms。
*   **稳定性：** 自动保存间隔 30 秒，崩溃恢复率 99%。
*   **隐私：** 所有数据默认本地存储，不上传云端（除非用户主动开启同步）。
